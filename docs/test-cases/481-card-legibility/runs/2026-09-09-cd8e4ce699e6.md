## Change and review findings

Integration with durable links #506 originally left two GitHub controls on each card and routed
the newer shared badge through a different, permissive parser. The old hover-only anchor could
bypass durable quarantine. The final card keeps the existing shared title-row badge, retains its
keyboard target and inward focus ring, and uses the strict shared leading-header parser only
when no durable GitHub row exists. Description edits refresh the modal PR link without saving
the draft or replacing durable issue identity.

Eight new issue/PR cases failed before the parser integration: marker text inside another record,
quoted non-leading headers, duplicate records and normalized URLs with query/fragment. All pass
afterward. Twelve old tests then correctly failed because they referenced removed component
fields; they now execute the compiled shared badge lifecycle and modal PR resolver, with actual
browser rendering checked separately. No assertion was removed to conceal a production failure.

Independent review found two more edges. The full-title browser assertion could pass with a
three-line clamp; it now compares scroll height to the actual visible title box. Ten new URL
suffix cases reproduced dropped closing parentheses and terminal punctuation before the fix.
The parser preserves the complete query/fragment token while retaining sentence-stop cleanup
for bare paths. Actual browser navigation and live draft PR previews use those punctuation cases.

## Failed attempts and limits

- The first full UI invocation could not load Playwright because this isolated checkout had no
  installed Node dependencies. `npm ci` restored the lockfile packages before execution.
- The next full UI run finished 51/52: the Home next-task link's URL wait timed out. The same
  case and complete suite passed in the subsequent run. No navigation product fix is claimed
  from that rerun; both logs are retained for later diagnosis if the intermittent failure returns.
- One Chromium card fixture retried a click after 150 ms while the opening panel's backdrop was
  already present. The log identifies backdrop interception. The fixture now waits for actual
  panel visibility before deciding whether another click is needed; all three engines passed.
- Restarting the owned test server left expected connection errors in earlier browser logs;
  final runs navigated afresh to the rebuilt app. CLI `### Error` output was always treated as a
  failure even when its process exit was zero.
