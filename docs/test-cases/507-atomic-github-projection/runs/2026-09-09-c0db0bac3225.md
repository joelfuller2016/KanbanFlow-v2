## Finding and repaired behavior

Independent review found that `portfolio-sync.mjs` already treats a quarantined link
without an issue number as a human decision affecting unmatched issues in that project
and repository. The shared projection service checked only matching issue numbers.
A direct REST/native/stdio request, or a sync using a cache read before the human decision,
could therefore create a replacement card.

The shared service now checks both cases inside its existing immediate SQLite transaction,
before task creation. Matching numbered quarantines keep their existing repository-wide
behavior. Unnumbered quarantines apply only to the target project and repository/provider,
even if a legacy quarantine happens to retain a different node ID. Exact active identity
replay remains before this refusal check and preserves current human-edited fields.

The refusal contains `quarantined-link-exists`, the actual review task ID and this complete
message, with the persisted task ID substituted for the placeholder:

```text
Task {taskId} has an unresolved quarantine without an issue number in this project and repository; resolve it before creating another projection.
```

REST returns 409. Native MCP exposes the conflict code and full message as a tool error.
Stdio exposes the REST 409 and structured conflict payload. No task, link, Created comment,
or audit write occurs. Existing quarantine content and timestamps remain intact.
