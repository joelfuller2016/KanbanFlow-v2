## Failed attempts and limits

JSON omits that property, so the correct fixture expectation removes the route-only field before deep equality. The production request was already correct. Full long-content equality was retained; an explicit empty string boundary was added and passed separately.

The broad UI failure occurred at #483's initial unguarded card-title click. The panel remained hidden for the 15-second wait. Surrounding scenarios already use `clickUntil` to handle the prerender-to-interactive boundary. The correction applies that same helper only to this opener and preserves every Tab/Shift+Tab/Escape/focus-return assertion. The source supports a missed prerender click as the explanation; no application interaction code was changed or silently declared fixed.

The next run passed #483 but observed the Ideas promote dialog before `OnAfterRender`/`initDialog` had moved focus from its opener. A bounded wait now observes focus entering that dialog; it does not move focus and therefore still fails if focus setup is missing. All original trap and restore assertions remain. The following broad run passed 52/52.

The existing broad `scripts/smoke-api.ps1` was also executed against its own fresh database and port 5210. Its owning checkout's temporary root held the logs/database; the scratch copy added an absolute containment check before recursive cleanup, kept the source repository root explicit, and inherited `Start-Process:WindowStyle=Hidden`. All API assertions before memory recall passed. The run then failed at `GET /api/memory/search` because its HTTP client timeout is fixed at five seconds. The optional embedding provider uses its own longer per-attempt budget, so that prerequisite needs a bounded approved verification environment. The original failure is retained in `api-smoke.log`; it is not an application-projection failure or a successful full API smoke.

Automatic execution approval rejected a proposed rerun with process-local `KANBANFLOW_LLM_TIMEOUT_MS=250`, reporting only **“blocked by policy.”** That command did not execute. The rejected action was not rerouted through another shell, helper or agent. The parent owns its already-approved combined-branch API verification. No normal provider configuration, model, credentials or access settings were changed. Keep the broad API acceptance item open until that result is recorded.

Human usability feedback is pending. The browser exercises an actual UI edit and audit, but automated checks do not constitute human approval. Native `get_task` read-shape parity, #511 integration and full legacy-content recovery remain separately tracked.
