## Smoke instance isolation (#522)

`workflow-smoke-instance.mjs` prepares an owned single-use manifest without starting a server or creating/deleting a database. The workflow harness verifies the loopback origin, manifest, unlinked owned database path, actual read-only admin health identity, explicit environment configuration and fresh startup before starting a wrapper or issuing mutations. Missing/wrong/reused targets fail before writes. The ledger retains successful, failed and interrupted evidence; cleanup remains explicit and manual. The [operating guide](../../../request-workflow.md#verification-and-local-operation) documents preparation, startup ownership, inspection and interrupted-run handling.

Instrumented CLI regressions intercept fetch and child-process startup. Unsafe inputs issue no calls; a wrong database permits only the read-only health GET; an accepted fixture proves identity before the intercepted wrapper startup and records the injected startup failure. These tests start neither a Kanban app nor a real wrapper for the guarded CLI paths. They do not establish that a full accepted run against a live disposable app succeeds.
