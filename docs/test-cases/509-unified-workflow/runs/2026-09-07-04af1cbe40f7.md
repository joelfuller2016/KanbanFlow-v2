## Reproduction and recovery

1. **Run the case from a fresh fixture.** Follow [TC-509](../README.md#automated-acceptance-checks). Expect both browser cases to return `passed: true`. Reusing an already-mutated navigation fixture caused duplicate link selectors during development; regenerate the fixture instead of relaxing the selector assertion.
2. **Inspect rendered evidence.** Wait for panel transitions and scroll the acknowledgement into view. The first mobile capture only showed the top of the internally scrolling request panel; the final case sets the mobile viewport before entry and captures the actual acknowledgement. A passing DOM check alone is not visual approval.
3. **Verify the normal app after rebuilding.** Keep a SQLite-consistent backup, stop only the owned launcher process, rebuild through the normal launcher, compare existing rows and follow the real human-review link. If validation fails, retain the backup and logs; do not overwrite user data or mark the task accepted.
4. **Record human feedback separately.** Use Updates for a decision, require the connected agent to acknowledge it, then inspect the revised plan/cards. U-10 remains Todo until a person performs the checks. Major UI changes require actual user testing before adoption.
