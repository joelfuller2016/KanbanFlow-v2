## Change and flow

Previously, Show in outline evaluated an unscoped page selector. The outline had no persistent current item or visit history, and its header scrolled with the tree. Now a feature/task/subtask identity is shared from ProjectView to ProjectOutline. Opening an item records a visit, expands required parents, highlights one row and scrolls the item container. Existing outline editors and task card flows are retained.

Show in outline releases the panel's focus trap, closes the card and reveals/focuses the current selected row. This includes a selected nested subtask when its parent card was opened from the outline's Add control. It opens the existing mobile outline drawer when needed. Back/Forward move through hidden project-visit history without reopening a panel. They skip deleted items, suppress consecutive duplicate visits and discard the forward branch after a new visit. Leaving the project or reloading starts a fresh history.

The fixed header contains the project title, existing actions and two history arrows. Only the item area scrolls. A [collocated JavaScript module](../../../../src/KanbanFlow/Components/Shared/ProjectOutline.razor.js) receives that container through a [typed wrapper](../../../../src/KanbanFlow/Components/Shared/ProjectOutlineInterop.cs), avoiding page-wide scrolling and global evaluation. Selection/history are presentation state; task and workflow records are unchanged by navigation. See the [before/after table and flow diagram](../../../plans/central-project-board-implementation.md#u-12--synchronized-outline-selection-and-hidden-visit-history).

## Findings and practical limits

The first browser assertion checked collapse before the Blazor event rendered. It now waits for the target to leave the DOM. The initial scroll snapshot also included filtering and opening a board card; it now brackets Show in outline specifically, while separate assertions verify automatic selection/reveal and the fixed header. Both were test timing/scope corrections; the final case runs from a fresh fixture at the recorded source.

The same-project query fix remains in place. Project changes now reload the new project's data and reset visit state, so hidden history cannot navigate into the previous project. Opening a task from the outline still opens its existing edit modal; selecting a subtask still opens its parent task editor while retaining the subtask's own highlight.

No API routes, schema or managed-agent execution behavior changed. Broad API smoke and the complete request-to-conclusion walkthrough were not rerun for this outline change. Their earlier evidence and default embedding-timeout limitation remain in the previous run chain and are not claimed for this commit. Browser automation and inspected screenshots do not constitute actual user usability approval.
