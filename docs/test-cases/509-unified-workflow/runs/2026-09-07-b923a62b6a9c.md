## Change and flow

Before, browser measurement showed a fixed 480px task panel at a 1280px viewport, with only a close icon. Now a fresh card opens at 50% width on desktop. **Full page** expands it to the viewport; **Half page** restores the right half; **Close** returns to the board. Below 992px either mode uses the available width for readability. The active size icon is marked visually and with `aria-pressed`. Reopening a closed card starts at half page.

The two size buttons only change a component field. They do not recreate the task panel, reload the task, navigate or write the database. CSS is scoped to [TaskDetailPanel](../../../../src/KanbanFlow/Components/Shared/TaskDetailPanel.razor.css), following [Blazor CSS isolation](https://learn.microsoft.com/aspnet/core/blazor/components/css-isolation?view=aspnetcore-10.0). Existing task edits and comments still use the shared task service and are visible to MCP.

## Development findings

The first display case caught a real accessibility/state-style defect: Razor boolean attributes rendered the true `aria-pressed` as empty and omitted false. The controls now emit the explicit strings `"true"` and `"false"`; the same case passes and the active-size styling works. No assertion was weakened.

Initial screenshots caught the button color transition. Final captures disable finite screenshot animations and were inspected at both widths and mobile size. This changes evidence capture only.
