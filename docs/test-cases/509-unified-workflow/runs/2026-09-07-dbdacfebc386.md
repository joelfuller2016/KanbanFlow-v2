## Reproduced failure and correction

At incoming head `2fe0531`, the decision, acknowledgement and revised plan persisted correctly. Clicking **Refresh saved details** refreshed the request panel, but the ordinary board retained the old card title. The browser case failed with `Human board still shows the old task.`

The handler only called `Refresh` on `RequestWorkspace`. The existing project-level `OnChanged="LoadProject"` callback was used after submissions but was absent from manual refresh. The correction calls that same callback after refreshing request details. The existing parent reload preserves filters, outline state and mounted editor identity. No new event system, polling, layout or controls were introduced.

The same scenario passed after the correction, including a retained unsaved brief and filter. The first harness attempt also failed before any write because its CLI execution scope lacks a global `URL`; URL parsing was moved into the browser context. A task-detail screenshot initially caught the opening animation; the final case waits for the panel to reach the viewport before capture. These harness issues were corrected without changing application behavior.

The callback follows the existing source convention and Microsoft's [Blazor EventCallback guidance](https://learn.microsoft.com/aspnet/core/blazor/components/event-handling?view=aspnetcore-10.0#eventcallback). Independent source review found no callback loop or additional blocker in this scoped correction. A separate possible selection-ordering race remains a source-level risk without a reproduction; this run does not claim to resolve it.
